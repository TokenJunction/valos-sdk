# Releasing valos-sdk

Every release is signed twice: the **git tag** is signed by a person, and the
**release artefact** is signed by CI with Sigstore and carries SLSA provenance.
No certificate, CA subscription or hardware token is involved.

## One-time setup: sign your tags

Use an SSH key you already have. It costs nothing, and GitHub shows a
"Verified" badge on the tag once the key is registered.

```bash
# 1. Tell git to sign with SSH instead of GPG
git config --global gpg.format ssh
git config --global user.signingkey ~/.ssh/id_ed25519.pub

# 2. Register the same key as a SIGNING key (not an auth key) at
#    https://github.com/settings/ssh/new  ->  "Signing Key"
#    Without this the tag is still signed, but GitHub will not mark it verified.

# 3. Optional: sign every tag by default in this repository
git config --local tag.gpgsign true
```

Test it on a throwaway tag before you rely on it:

```bash
git tag -s test-signing -m "probe" && git verify-tag test-signing && git tag -d test-signing
```

### Alternative: gitsign (keyless, no key at all)

If you would rather have no long-lived signing key on disk:

```bash
brew install sigstore/tap/gitsign            # or: go install github.com/sigstore/gitsign@latest
git config --global gpg.x509.program gitsign
git config --global gpg.format x509

git config --global tag.gpgsign true
```

Trade-off: gitsign tags are verifiable with `gitsign verify`, but **GitHub shows
them as unverified** because GitHub does not check Sigstore signatures on git
objects. Choose SSH signing if the verified badge matters to you.

## Cutting a release

The version in `package.json` is the source of truth. The workflow refuses to
publish if the tag and `package.json` disagree.

```bash
# 1. On main, with the release commit checked out and CI green
node -p "require('./package.json').version"     # expect 0.1.0

# 2. Signed, annotated tag. -s is required: an unsigned tag fails the build.
git tag -s v0.1.0 -m "valos-sdk 0.1.0"

# 3. Verify locally before pushing
git verify-tag v0.1.0

# 4. Pushing the tag is what publishes
git push origin v0.1.0
```

## What CI does with that tag

1. Rejects the run if the tag is not signed, or if it disagrees with `package.json`.
2. Runs `npm ci`, lint and the full test suite.
3. Builds reproducibly with `SOURCE_DATE_EPOCH` pinned.
4. Packs the tarball, writes `SHA256SUMS`.
5. Signs the tarball keyless with Sigstore, writing `<tarball>.bundle`.
6. Emits SLSA provenance bound to that tarball.
7. Creates the GitHub release with the tarball, checksums and bundle attached.

The signing identity is the workflow itself:
`https://github.com/TokenJunction/valos-sdk/.github/workflows/release.yml@refs/tags/v0.1.0`,
issued by `https://token.actions.githubusercontent.com`. There is no long-lived
key to leak or rotate.

## How a consumer verifies a download

```bash
V=0.1.0
gh release download "v$V" --repo TokenJunction/valos-sdk

bash scripts/verify-release.sh "$V" .
```

That script checks the checksum, the Sigstore signature against the expected
workflow identity, and the provenance attestation. To do it by hand:

```bash
sha256sum -c SHA256SUMS

cosign verify-blob \
  --bundle "valos-sdk-$V.tgz.bundle" \
  --certificate-identity-regexp '^https://github\.com/TokenJunction/valos-sdk/\.github/workflows/release\.yml@refs/tags/v.*$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  "valos-sdk-$V.tgz"

gh attestation verify "valos-sdk-$V.tgz" --repo TokenJunction/valos-sdk
```

## What level of SLSA this is

Build L2 is a fair claim: provenance is generated by GitHub's hosted builder,
signed with an OIDC identity, and records the exact commit and workflow.

Build L3 is **not** claimed. L3 requires a build platform where user-defined
steps cannot influence the provenance, which in practice means a hardened
reusable workflow or a dedicated builder. Do not describe this project as L3 in
the badge form or anywhere else until that changes.

## Troubleshooting

**"tag v0.1.0 is not signed"** — you tagged with `git tag v0.1.0`. Delete and
redo it: `git tag -d v0.1.0 && git tag -s v0.1.0 -m "valos-sdk 0.1.0"`.

**"tag does not match package.json"** — bump the version in a commit, merge it,
then tag that commit. Do not move a published tag; cut a new patch version.

**"failed to verify signature" on the tag** — your public key is not in
`allowed_signers`, or you have not registered it as a signing key on GitHub.
`git config --get user.signingkey` should point at the `.pub` file.
